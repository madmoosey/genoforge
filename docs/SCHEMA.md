# Schema

Two stores, one rule (ADR 0002): **Postgres for entities with identity,
lifecycle and joins; MongoDB for high-cardinality semi-structured records.**
This page covers the Postgres half; the variant document model arrives with
the MongoDB repository (PR 7).

## Postgres (Django ORM, `python/genoforge/apps/`)

```
Sample 1 ──< SequencingRun 1 ──< PipelineRun 1 ──< PipelineStep
  (PROTECT)        (PROTECT)          (CASCADE)   ├──< FileArtifact
                                                  └──< QcMetric
```

| table | identity | notable rules |
|---|---|---|
| `samples_sample` | `external_id` unique | timestamps |
| `samples_sequencingrun` | `(sample, fastq_sha256)` unique | `fastq_sha256` is the **ingestion idempotency key**; check constraint: PE needs `fastq_r2`, SE must not have it; sha256 validated as lowercase hex |
| `runs_pipelinerun` | UUID pk | `status` + `pipeline_version`; `finished_at` requires `started_at`; composite index `(status, started_at desc)`; **partial index** on `seq_run where status = 'running'` for the "what is running" query |
| `runs_pipelinestep` | `(run, name, attempt)` unique | `attempt >= 1`; retries are new rows, so flaky-stage history is kept |
| `runs_fileartifact` | `(run, kind, path)` unique | `bytes`, `sha256` to detect a file changing underneath a resume |
| `runs_qcmetric` | `(run, stage)` unique | typed columns for the metrics worth filtering/charting; every fraction column has a `[0, 1]` check constraint; `details` JSONB with a **GIN index** for the long tail (per-position arrays, tool-specific extras) |

### Why these choices

- **PROTECT upward, CASCADE downward.** Deleting a sample while runs exist is
  refused; deleting a pipeline run removes its steps, artifacts and metrics.
  Inputs are the audit trail; outputs are reproducible.
- **`TextChoices`, not DB enums.** Adding a status is a code change and a data
  migration, never an `ALTER TYPE` with its locking caveats.
- **Constraints on the model, not only in the DB.** Django validates
  `UniqueConstraint`/`CheckConstraint` in `full_clean()`, so the admin and any
  form give a named, human error before the database gets a chance to.
  `tests/python/integration/test_models.py` checks every rule at both layers.
- **Typed columns + JSONB, not one or the other.** `q30_frac` is a column
  because dashboards filter on it; `per_position_mean_qual` is JSON because
  nothing filters on element 37. The GIN index keeps containment and key
  lookups on `details` indexed anyway.
- **Partial index for the hot query.** The running set is tiny; the index is
  too.

### Migrations

Generated by `makemigrations`, committed, and guarded two ways in CI:
`makemigrations --check` fails on drift, and a test migrates both apps to zero
and back.

## MongoDB (PR 7)

`variants` collection, one document per call, `_id = run:<uuid>:<chrom>:<pos>:<ref>:<alt>`
so loads are idempotent; indexes on `(run_id, chrom, pos)` and `(sample, chrom, pos)`.
